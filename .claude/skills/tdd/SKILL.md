# tdd

RED → GREEN → REFACTOR のサイクルで、テストを先に書きながらロジックを実装する。各フェーズの境目で必ず検証コマンドを回し、「正しい状態」を確認してから次へ進む。

## 対象範囲

テスト可否を分けるのは「純粋関数か」ではなく「**実行環境（GPU / D3D11・WGC / WPF・WinForms のメッセージループ / ウィンドウ・モニタ）に依存するか**」。xUnit のテストは通常の .NET プロセスで走るので、素の値（数値・文字列・配列・プレーンなオブジェクト）と標準ライブラリだけで動くコードはそのままテストできる。`ID3D11Device`・`GraphicsCaptureItem`・`HWND`/`HMONITOR`・WPF/WinForms のウィンドウやフックに触れるコードは、実ハードウェア／デスクトップ環境が要るのでユニットテストには向かない（純粋関数でも、これらの型を引数に取ればモックが要る）。

- **TDD する**: `Imaging/`（`ToneMapper` のトーンマップ演算・正規化・sRGB 変換、`HdrFrame` の `Crop` など）や、数値・配列・プレーンなオブジェクトだけで完結し環境に依存しない計算。実 GPU もデスクトップも要らないのでそのままテストできる。
- **そのままでは TDD しない**: `Capture/`（D3D11 デバイス生成＋WGC でのフレーム取得）・`Interop/`（Vortice↔WinRT 相互運用、`HMONITOR`/`HWND` 解決、グローバルホットキー）・`UI/`（トレイ常駐・矩形選択オーバーレイ・設定ウィンドウ）の、実行環境に直接触るグルー。実 GPU／デスクトップ／メッセージループが要るのでユニットテスト向きでない。
- **抽出できるなら抽出する（ただし程度問題）**: その中に検証する価値のある計算（クランプ・補間・座標/矩形の変換、モニタ矩形の合成、感度スケーリング、状態遷移、設定値の正規化など）が埋まっていたら、環境に依存しない関数として切り出して TDD する。一方で**テストのために設計を歪めない** — 不自然な型変換や薄い間接層が増えるだけなら、無理に出さずグルーのまま対象外にする。判断材料は reference.md の「テスト可否を分ける軸」「レイヤと抽出方針」。

## サイクル

### RED — 失敗するテストを先に書く

これから足す/直す振る舞いを表すテストを書く。**実装コードはまだ書かない**。

正常系だけでなく、**退化・境界の入力（ゼロ・空・0 除算・範囲端・負値・オーバーフローなど）もここで洗い出してテストに含める**。GREEN は「テストを通す最小」なので、RED で書かなかったケースは実装されない（例: 矩形クランプなら幅0・画面外、トーンマップなら黒・SDR 白・白飛びする 1.0 超）。逆に、起きえない入力のために投機的な分岐を増やす必要はない。

`dotnet test` を回し、**そのテストが、まだ実装が無いという正しい理由で失敗している**ことを確認する。落ちない・別の理由（ビルドエラー等）で落ちる場合はテスト側を直す。失敗を確認できて初めて次へ進む。

### GREEN — 最小実装で通す

そのテストを通すだけの**最小限**の実装を書く。先回りして使われていない分岐や汎用化を足さない（それは次の機能の RED で driving する）。

`dotnet test` を回し、**全テストが緑**になることを確認する。

### REFACTOR — 緑のまま整理する

テストを緑に保ったまま、命名・重複・見通しを整える。リファクタ中も小まめに `dotnet test` で緑を保つ。

仕上げに `dotnet build`（コンパイル＆型チェック）と `dotnet format`（.editorconfig に沿った整形。自動修正される）を回し、**エラー・警告が残っていない**ことを確認する。制御フローが深くなって読みにくくなったときの扱いは CLAUDE.md「複雑度と設計見直し」に従う（既定は再設計。数値を通すためだけの機械的分割はしない）。

## 完了ゲート

次の 3 つが揃って初めて「完了」とする:

1. `dotnet test` が全緑
2. `dotnet build` がエラー 0（新規の警告も残さない）
3. `dotnet format --verify-no-changes` がクリーン（整形差分なし）

このプロジェクトの具体的なコマンド・テストの書き方（xUnit v3 / 日本語の `DisplayName` / `test/Lukit.Tests` 内の置き場所・命名 / `internal` の見せ方 / 浮動小数点の比較）・抽出の指針は [reference.md](reference.md) にまとめてある。サイクルに入る前に一読する。
