# 設計

## 草案

- これはなに？
  - Windows で動作するスクリーンショットアプリ
- 目的は？
  - Snipping Tool ではHDR環境時にスクリーンショットが正しく撮れない問題があるため
    - HDR対応のオプションを有効にしてもダメ
    - わざわざディスプレイ設定を都度SDRに変えてから撮ってる
- 機能
  - must
    - HDR環境下でも正しくとれる
    - 画面全体のスクリーンショット
    - ウィンドウ全体のスクリーンショット
    - 選択範囲のスクリーンショット(矩形選択)
    - ほかのディスプレイでもスクリーンショットが撮れること
  - more
    - MacのSkitchのようにスクリーンショット撮った後に注釈とかもつけたい
    - MacのQuickTimeのようにデスクトップの録画もしたい
      - その場合はトリミングとかも欲しい

## 命名

- **正式名：Lukit Tools** / **通称：Lukit（ルキット）**
- タグライン（HDR はここで言う）：
  > HDR でも色が破綻しない、Windows で **撮る・録る・注釈・渡す**

| 項目         | 値                   |
| ------------ | -------------------- |
| 正式名       | Lukit Tools          |
| 通称         | Lukit                |
| 実行ファイル | `Lukit.exe`          |
| リポジトリ   | `lukit-tools`        |
| 名前空間     | `lukit`              |
| ドメイン候補 | `lukit-tools.xxx.xx` |

### 命名の考え方（哲学）

- **core why**：このツールが欲しい根本理由は「**相手に “今こうなってるか” を忠実に渡したい**」。
  スクショ・録画・注釈は全部その手段で、目的は *現状の忠実な共有*。
- つまり本質は「スクショツール」ではなく「**現状共有ツール**」。
  柱は **撮る（静止画）・録る（動画）・注釈・渡す（共有）** の 4 本。
- 機能を名前に詰め込むと将来ブレる（HDR / Tone / Chroma 等は狭すぎる）。
  → **名前は抽象ブランドにして、HDR は名前でなくタグラインで言う**。
- 動機は「HDR でまともに撮れないのは糞」という素朴なもの。だが裏の軸は
  **fidelity（ありのまま）＋ communication（伝える）**＝実直さ。
  → 奇をてらわない実直な名前がむしろ合う。

### なぜ Lukit Tools か

- **読みやすい・言いやすい・気に入っている**（ルキット）。名前は一目で読めるのが大事。
- 読みやすい `look / peek` 系の近所を一通り当たった結果、**素の Lukit の衝突が最も軽い**
  （オフジャンル・無名。下表参照）。
- **"Tools" 接尾**で以下を同時に解決：
  - ドイツの同名アプリ "lukit" と正式名で分離できる（検索・表記の見分け）。
  - 「撮る・録る・注釈・渡す」の**道具箱**という実態に嘘がない。
- **Snipping Tool との対比**が効く：置き換え対象の Microsoft "Snipping **Tool**"（単数・snip のみ）
  に対し "Lukit **Tools**"（複数＝撮る・録る・注釈・渡す）。名前だけで
  「単なる snip じゃない・ちゃんと動く後継」というカテゴリとポジションが伝わる。
  出自（＝HDR でまともに撮れない Snipping Tool への対抗）も名前に刻まれる。
- ShareX 的な「実直な多機能ユーティリティ」の顔になり、上記の哲学と一致。
