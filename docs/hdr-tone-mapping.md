# HDR とトーンマッピングの仕組み

Lukit Tools が HDR 環境でも色を破綻させずにスクリーンショットを撮れる理由と、その内部処理・トラブルシューティングをまとめる。アプリの概要と使い方は [README](../README.md)、初期の設計草案は [design.md](design.md) を参照。

## なぜ HDR だと白飛びするのか

HDR を有効にすると、Windows デスクトップは **scRGB**（リニア・Rec.709 原色・`1.0 = 80 nit`、[0,1] を超える値を持つ）で合成されます。SDR コンテンツの「白」も、SDR 輝度設定に応じて `SDR白色輝度 / 80` 倍にスケールされます（例：SDR 白 = 480 nit なら scRGB **6.0**）。

古い取り込み方式や、この正規化を行わないツールは、scRGB を **そのまま [0,1] にクリップ**してしまうため、

- 50% グレー（scRGB 3.0）→ クリップされて **真っ白（255）** に
- 中間調が持ち上がり、コントラスト・彩度が失われて **乳白色** に

という「白飛び」が発生します。

## Lukit Tools の解決方法

1. **FP16 で取り込む** — Windows Graphics Capture API を `DXGIFormat.R16G16B16A16Float`（scRGB）で使用し、HDR の広ダイナミックレンジ・広色域をクリップせず保持。
2. **SDR 白色輝度を自動検出** — `DisplayConfig`（`GET_SDR_WHITE_LEVEL`）から、そのモニタの実際の SDR 白 nit を取得。
3. **トーンマップして SDR 化** — `scRGB ÷ (SDR白 / 80)` で正規化 → 必要ならハイライトをロールオフ → sRGB ガンマを適用。scRGB と sRGB は原色が同じ（Rec.709）なので色域変換は不要。

これにより SDR コンテンツは「見たままの」明るさ・コントラストで保存され、真の HDR ハイライトも破綻せずロールオフします。

### トーンマップ演算子

| 演算子 | 用途 |
|---|---|
| `Reinhard`（既定） | 輝度保存の拡張 Reinhard。ハイライトを自然にロールオフ。SDR 部分はほぼ無変化 |
| `Clip` | [0,1] にクリップするだけ。最速。真の HDR ハイライトは飛ぶ |
| `AcesFilmic` | ACES 風フィルミック。コントラスト強め |

## トラブルシューティング

- **保存画像が暗すぎる / 明るすぎる**：`--display-info` で検出値を確認。自動検出が実態と合わない場合は Settings で SDR 白色輝度を手動指定。
- **真の HDR ハイライト（動画・ゲーム）を強調したい**：演算子を `AcesFilmic` に。
- **ホットキーが効かない**：他アプリと競合している可能性。Settings で別の組み合わせに変更。
